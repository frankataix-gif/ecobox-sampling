# P1 改造点清单（修订版）：取样独立 · 矿区自动归属 · 矿证资料页

基线：`ecobox-sampling` @ `f8ed627`（b102）；改造后 `b20261102-104` / SW `sampling-v7`。

## 0. 设计修正（先说结论）

原方案「先选矿区 → 再取样」是错的，已于本版推翻：

- **现场取样是独立动作**：只负责「定位 + 记录 + 拍照」，去哪取样由 GPS 和现场判断决定，工具不该在流程开头拦一道「请选择矿区」。
- **矿区归属是记录的派生属性**：由坐标反推（`areas.json` 的 bbox），落在范围外就记「未归属」，不阻塞保存、不影响编号、不影响离线。
- **矿证 / 地质资料是浏览型内容**：单独一个页面（`licences.html`）承载，和取样工具解耦；改资料不用碰取样代码。

因此：

| 项 | 旧（已废弃） | 现方案 |
| --- | --- | --- |
| 取样流程 | 先选矿区 chip | 直接取样，无选择步骤 |
| 本地库 | `samples_<areaId>` 多库 | 单一 `samples` 库（一条同步队列） |
| 编号 | `SER-S20261102-001` | `S20261102-001`（全局唯一） |
| 矿区字段 | 用户选择 | `area_id` 由坐标自动判定 |
| 资料页 | 无 | `licences.html` + `licences.json` |

## 1. 现状核对结论（审计，仍然有效）

| 文件 | 作用 |
| --- | --- |
| `sampling_helper.html` | 全部前端：IndexedDB、GPS、拍照、地图、轨迹、同步 |
| `sampling_sw.js` | PWA 离线缓存 |
| `geo_packs/` | 离线地图包（`index.json` + `<id>.json` + 瓦片） |
| `manifest.json` / `index.html` / `clear.html` | PWA 入口与清缓存页 |
| — | **仓库内没有 worker 源码**，后端只在线上运行 |

数据层：`idb()` 打开 `field_sampling`，store 为 `samples`（含照片 Blob）/ `tiles` / `kv` / `track` / `trips`。

### 后端（已核实）

- 类型：**Cloudflare Worker**（`fancy-heart-7a80`，响应头 `Server: cloudflare`），绑定 **D1**（binding `DB`）。
- 表：`samples(sample_id TEXT PRIMARY KEY, data TEXT, created_at, updated_at)`。
- `/sample` 把整条样品 JSON（**照片 base64 内嵌**）写入 D1；`GET /samples` 实测 36 条 / 56 MB，其中 53 MB 是照片。**照片没有进 R2**（账号里有 `ecobox-media`，但未绑定）。
- 接口：`/ping`、`POST /sample`、`GET /samples`、`GET|DELETE /sample/<id>`、`POST /ocr`。
- 线上根路径是旧版页面（约 98 KB），与 Pages 上的版本已不同步。

### 必须在 P2 修的问题

1. **接口无鉴权**：`APP_TOKEN` secret 绑定已删除，`if (env.APP_TOKEN && …)` 直接放行。任何人都能拖走全部样品与照片。
2. **照片压 D1**：单行数 MB，继续增长会撞 D1 行/查询上限，也拖慢 `/samples`。
3. **`/ocr` 不可用**：`OPENAI_KEY` 未配置；P4 改用 Gemini 2.5 Flash。
4. 线上根页面与 Pages 版本漂移，需要统一发布源。

## 2. 改造点（按文件）

### `sampling_helper.html`

- **矿区模块 → 只做归属判定**：`AREAS_FALLBACK` / `loadAreas()` / `applyAreaDoc()` / `areaAt(lat,lon)` / `areaName(id)`；
  删除 `AREA.cur`、`renderAreaBar()`、`switchArea()`、`areaStoreName()`，页头恢复为普通标题栏。
- **数据层**：`S` 只操作单一 `samples` store；`ensureBaseStores()` 不再按矿区建表；加矿区不再升级 DB version。
- **保存**：`rec.area_id = (areaAt(lat,lon) || 未归属).id`；`licence` 仍由 `licAt(lat,lon)`（矿证范围）判定。
  编辑时保留原 `area_id`，不因坐标微调改写归属。
- **编号**：`nextSid()` 回到全局 `S/M + 日期 + 序号`。
- **列表 / 详情 / CSV / 备份 / 上传**：全部去矿区过滤；`area_id` 仅作为字段随记录走（`license_no` 保留兼容 D1）。
- **兼容处理**：`mergeLegacyStores()` 在首启把试验版遗留的 `samples_*` 并回 `samples`（去重按 `sample_id`，写 `kv.areas_merged_v2`），避免已产生的数据丢失。
- **设置页**：原「矿区（分区保存）」卡片改为说明「取样不需要选矿区」+ 资料页入口。
- 保留上版的两个修复：设置页 token 回填、存储可用性改用 `idb()` 检测（新装不再误报）。

### `areas.json`（配置驱动，只服务归属）

```json
{ "id": "serenje_1330nw", "code": "SER", "name": "Serenje 1330NW",
  "bbox": [30.0, -13.45, 30.5, -12.95], "center": [30.25, -13.2],
  "licences": ["42881-HQ-LEL"], "map_pack": "serenje" }
```

- `bbox = [west, south, east, north]`（WGS84），用于坐标归属；`licences` 用于把矿证关联到矿区；`map_pack` 供离线地图包选用。
- 现有 3 个：Serenje 1330NW、Kalomo（南部）、Chitambo 1230SE。新增矿区只改此文件。

### `licences.json`（新增）

每条矿证：`no / area_id / holder / type / status / 有效期 / commodities / center / geology{terrane,host,structure,minerals,alteration,notes} / sampling{target,spacing,note}`。
**未知字段显式写「（待核实）」**，不编数据。

### `licences.html`（新增页面：矿证与地质资料）

- **只有矿证**：侧栏就是矿证项目列表（按矿区→证号排序，显示证号/矿区/状态），点一条右边出详情；没有其它导航入口。
- 右侧四个分类 tab：**项目介绍 / 项目地图 / 项目地质报告 / 项目信息**。
  - 项目介绍：`intro` + 矿权信息 + 地质背景 + 取样要点。
  - 项目地图：OSM 嵌入 + 中心坐标 + 复制坐标 + 去取样（离线时不显示地图框）。
  - 项目地质报告：读 `licences.json` 的 `reports`，空态给出登记格式。
  - 项目信息：该矿证的动态流（文字 + 压缩图 + 标签 + 留言），先落本机 `lic_feed_v1`，P2 接云端。
- 登录闸门在同页；配置缓存进 localStorage（`lic_cache_v1`），断网也能看上次的数据。
- 纯静态，读 `areas.json` + `licences.json`；SW 预缓存页面，配置走网络优先 + 离线回退。

### `sampling_sw.js`

- `CACHE` → `sampling-v11`；`PAGES` 增加 `licences.html`；`CONFIG` 增加 `licences.json`（网络优先，改文件刷新生效）。

## 3. 验收清单

1. 打开取样页：**没有任何矿区选择控件**，可直接定位、拍照、保存。
2. 在 Serenje bbox 内保存 → `area_id=serenje_1330nw`；在 bbox 外保存 → `area_id=""`（未归属），保存不受影响。
3. 同一天连续保存 → 编号连续递增，不因跨矿区断号/重号。
4. 断网刷新：取样页、资料页、矿区配置都可用（SW + kv + 内置 fallback 三层）。
5. 打开资料页：矿证卡片、矿区筛选、展开详情、地图链接正常；改 `licences.json` 刷新即变。
6. 有试验版 `samples_*` 分区数据时首启：自动并回主库并标注矿区，`kv.areas_merged_v2=true`。
7. 上传/CSV/备份：`area_id`、`licence` 字段随记录带出。
